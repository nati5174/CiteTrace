METHODS & LIMITATIONS

Evidence before confidence.

An exploratory citation-retrieval pilot, not a validated accuracy benchmark. This page separates recorded observations from what remains unknown.

01 / RESEARCH QUESTION

What came back, and what can we verify?

CiteProbe makes the difference between retrieving a scholarly record and verifying its identity inspectable. The pilot observes title, author and year searches for selected papers, then evaluates candidates using verified-identifier evidence.

It does not measure AI-generated text detection, plagiarism detection, or another product’s performance. The public pilot does not establish robustness to metadata mutations; a separate study would be needed.

02 / SAMPLE SELECTION

Eight selected arXiv source papers

Two papers per fixed first-submission-age cohort: 1–7, 8–14, 15–30 and 31–60 days, relative to 9 November 2026 UTC. Selection uses prespecified cs.CL source days and a frozen curator-reviewed dataset. It is not a random or representative sample of all scholarly literature.

“Source-verified” describes the citation metadata and curator provenance. It does not mean that a provider candidate matches, or that a paper is peer reviewed. Canonical source identities and the frozen dataset checksum are preserved.

03 / RECORDED PROVIDER SEARCHES

Sixteen evaluated searches

One metadata-only search per paper per provider: eight OpenAlex and eight Crossref searches. The recorded query combines title, authors and year; no DOI or arXiv identity hint is submitted. Parameters are copied from saved requests into the sanitized experiment manifest, not reconstructed from current API behavior.

All sixteen evaluated searches returned HTTP 200. Two earlier OpenAlex 429 attempts remain separate operational evidence and are excluded from these retrieval-quality observations. Network failures must not be treated as empty search results.

04 / ACCESS CONDITIONS

Unequal access limits direct comparisons

The first OpenAlex search was anonymous. The other seven OpenAlex searches used an API key. All eight Crossref searches were anonymous. These modes are supported by saved capture metadata, the continuation plan and the credential-injecting transport implementation; authentication values are never published.

The access-condition change is confounded with paper identity. This pilot cannot isolate an authentication effect, and provider scopes and search behavior differ.

05 / CANDIDATE EXTRACTION & RANKING

Provider order stays intact

Both requests limit retrieval to five records: OpenAlex per_page=5, Crossref rows=5. The version-1 adapters inspect the first five response entries and preserve one-based provider ranks, without local re-ranking or pagination. Unparseable entries would produce warnings; these sixteen saved lookups have none.

OpenAlex returned one candidate entry from one search; Crossref returned forty entries from eight searches. The 41 entries contain 40 distinct DOI values. Entries are not necessarily unique papers. Provider-side ranking algorithms are not recorded.

Extraction and normalization details

OpenAlex uses the results array, title, authorship display names, publication year and identifiers. Crossref uses message items, the first title, author names, and the first available publication/issued date used by the adapter. DOI URL prefixes are removed; arXiv identifiers are extracted from recognized URLs. Text fields trim surrounding whitespace. The manifest distinguishes inspected adapter code from the unrecorded historical checkout.

06 / IDENTITY JUDGMENTS

Undetermined is different from incorrect

Verified canonical identifiers or provenance-backed same-work/different-work mappings support identity decisions. Similar titles, overlapping authors or different identifiers alone do not establish identity or distinctness.

Correct
Verified evidence establishes that the candidate represents the source work.
Incorrect
Verified evidence establishes that the candidate is distinct from the source work.
Undetermined
Evidence is insufficient to establish either identity or distinctness.

All 41 candidate entries are UNDETERMINED. No candidate is confirmed correct or confirmed incorrect. The unchanged judgment explanation is “No verified evidence of identity or distinctness.”

07 / EVIDENCE-BOUND CALCULATIONS

Bounds on identity evidence, not accuracy scores

Recall@5 asks whether the target work can be established among up to five returned candidates. The lower count is the number of searches with a confirmed match. The upper count adds searches whose match status remains unresolved. Divide these counts by eight searches per provider.

lower = confirmed hits / 8
upper = (confirmed hits + unresolved searches) / 8

The frozen evidence bounds are 0–1 / 8 for OpenAlex and 0–8 / 8 for Crossref. No-result searches have no retrieved candidate that can be a match. These are identity-evidence bounds, not confidence intervals or estimates that candidates are correct.

Return counts are separate: OpenAlex 1 / 8 searches and Crossref 8 / 8 searches returned candidates. More returned candidates do not establish higher accuracy.

08 / REPRODUCIBILITY & PROVENANCE

Inspect and recalculate the public record

The pilot data contains source metadata, provider ranks, candidate identities and explanations, plus frozen research identifiers. The experiment manifest contains sixteen non-secret request parameter sets, endpoints, capture times, statuses, access modes, artifact hashes, extraction rules and explicit provenance gaps.

The historical Git checkout, precise header-arrival times and provider ranking internals are not_recorded. The manifest’s inspected adapter revision identifies code reviewed for the manifest, not a claimed historical execution checkout. Capture start/finish times are not a measurement of indexing latency.

Use the offline verifier with the two JSON files to reproduce public parsing, checksum/inventory checks, provider-return comparisons, candidate counts and evidence-bound calculations. Python 3.12+ and its standard library are sufficient; no API requests are made.

python verify.py data.json experiment-manifest.json

Original raw responses and credentials are excluded. Public consistency checks do not authenticate private captures or independently verify candidate identity. A new API request is a replication attempt under potentially changed conditions, not a replay of the frozen historical experiment.

09 / LIMITATIONS

What this pilot cannot establish

  • The small, selected eight-paper sample does not support population-level conclusions or statistical comparisons.
  • Different access conditions and provider scopes limit direct comparability.
  • All candidate identities remain unresolved; no provider-wide accuracy is demonstrated.
  • An empty search means no candidates were returned, not that a paper is missing from a database.
  • This is cross-sectional retrieval under recorded queries, not indexing latency.
  • No confidence intervals or significance tests are presented.
  • Historical reproducibility is partial because raw captures are private and some provenance fields are not recorded.

Curator verification and origin labels are supported by retained provenance, not independently guaranteed. Published metadata remains a frozen observation even if providers later update their records.

10 / FUTURE WORK

Separate studies, clearly labeled

Possible next steps include an independently reviewed identity-verification study, a broader prespecified sample, matched access conditions, repeated observations for latency questions, and a separately designed metadata-mutation experiment. None has been performed as part of this frozen pilot.
