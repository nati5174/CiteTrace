Understand identity evidence and Recall@5
Identity evidence
Verified identifiers or supported mappings connecting a returned record to the source paper. Similar wording alone is not proof.
Recall@5 evidence bounds
Among the first five returned records, the lower count includes searches with a confirmed match. The upper count adds searches where a match remains possible but unresolved. Divide by eight searches per provider. These are identity-evidence bounds, not confidence intervals.
No candidates returned
The recorded query returned an empty list. This does not establish absence from the provider’s database.

Read this pilot within its limits

Eight selected papers. Unequal access conditions. All candidate identities unresolved. No demonstrated provider-wide accuracy or indexing-latency conclusion.

Access conditions and historical limits

One OpenAlex search was anonymous; seven used an API key. All eight Crossref searches were anonymous. Access conditions changed alongside paper identity, limiting direct comparability. The selected cs.CL sample does not support population-level conclusions. Raw captures are private, so historical reproducibility is partial.

03 / RESEARCH APPROACH

Designed to leave
room for doubt.

The question is what a metadata search returns, and what identity evidence supports. This pilot is not a validated accuracy benchmark, a test of AI-generated text detection, or an evaluation of another product.

Review methodology
01

Source records first

Eight source-verified arXiv papers, two per fixed submission-age cohort. Source verification is a curator assertion supported by retained provenance.

02

Search without identity hints

Title, authors and year only. Canonical identifiers are withheld from provider queries. Up to five candidates per search; no local re-ranking.

03

Preserve uncertainty

Different titles or identifiers alone do not prove an incorrect match. Verified identity requires supporting evidence. All 41 entries remain undetermined.

04 / REPRODUCIBILITY

Inspect the data.
Recalculate the summary.

The public files expose the recorded results and sanitized request provenance. You can check the deterministic calculations without contacting a provider.

What is inspectable

Eight sources, sixteen searches, 41 candidate entries, return counts, provider ranks, identity judgments and explanations, frozen identifiers and checksums.

What can be reproduced

Public-data parsing, inventory checks, provider-return comparisons, candidate counts and Recall@5 evidence-bound calculations.

What cannot be replayed publicly

Private original responses, unrecorded headers or historical code checkout, provider ranking internals, and identity verification that has not been performed.

Verify the downloaded files locally

Save all three files in one folder, then run:

python verify.py data.json experiment-manifest.json

The verifier checks the data checksum, source/search inventory, rankings and judgments, then prints provider counts and evidence-bound counts. It checks consistency, not independent authenticity or identity.

A new API request is a replication attempt under potentially changed conditions, not a replay of the frozen historical experiment. Missing provenance is explicitly marked not_recorded. Raw captures and credentials are excluded.
